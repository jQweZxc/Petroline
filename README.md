# MVP программы контроля насоса

Проект представляет собой веб-приложение для анализа данных работы насоса. Программа читает JSON-файлы, проверяет их формат, рассчитывает время работы, остановки, пропусков и недостоверных измерений, а также визуализирует показатели давления и оборотов на графике.

## Как запустить проект

1. Клонируйте репозиторий на свой компьютер:
   ```bash
   git clone https://github.com/jQweZxc/Petroline.git
2. Откройте папку проекта в Visual Studio Code.
3. Установите расширение Live Server (автор: Ritwick Dey), если оно еще не установлено.
4. Откройте файл index.html, нажмите правой кнопкой мыши в любом месте кода и выберите Open with Live Server.
5. Приложение откроется в браузере. Выберите нужный файл из выпадающего списка для анализа.

Структура решения
Проект разделен на логические модули для удобства поддержки и чтения кода:

    index.html и css/style.css — разметка и стили пользовательского интерфейса.
    js/validator.js — проверка формата данных. Проверяет наличие обязательных полей, корректность типов данных и строгий рост времени. При обнаружении ошибки возвращает понятное сообщение и блокирует дальнейший расчет.
    js/calculator.js — бизнес-логика. Рассчитывает длительности интервалов (работа, остановка, пропуск, недостоверные данные) и режимы работы (low, normal, high) строго согласно правилам из rules.json.
    js/app.js — связывает все модули, управляет загрузкой файлов и отрисовкой двухосевого графика с помощью библиотеки Chart.js.

Тестирование и самопроверка
В папке data находятся 10 тестовых файлов, покрывающих основные сценарии:

    01_small.json, 02_boundaries.json — базовая работа и проверка граничных значений.
    03_gap_20min.json, 04_invalid_values.json — проверка обработки пропусков и недостоверных данных.
    05_long_record.json — комплексная проверка на длинной записи со сменой режимов.
    06_empty.json, 07_single_point.json — крайние случаи (пустой массив, одна точка).
    08_missing_rpm.json, 09_wrong_type.json, 10_duplicate_time.json — проверка корректной обработки ошибок формата.

Результаты расчетов для файлов 01–07 автоматически сверяются с эталонными значениями в файле expected_results.json. Файлы 08–10 корректно отклоняются программой с выводом текстового сообщения об ошибке, расчетные итоги при этом не показываются.
План проверки гипотезы (Диагностика)
В предоставленных синтетических данных нет подтвержденных случаев промытия. Однако встречаются интервалы с valid=false при формально нормальных значениях давления и оборотов (например, в файле 05_long_record.json на интервале 600–609 секунд).
Гипотеза: Такие интервалы могут указывать на кратковременный сбой датчика, электромагнитные помехи в линии связи или начало развивающейся неисправности (например, кавитации), которая еще не привела к критическому падению основных параметров, но была зафиксирована системой контроля качества данных как недостоверная.
План проверки:

    1. Сопоставить временные метки интервалов с valid=false с журналом технического обслуживания и журналом событий АСУ ТП за тот же период.
    2. Запросить данные с дополнительных независимых датчиков (например, вибродатчиков или датчиков температуры подшипников) за эти же промежутки времени для перекрестной проверки.
    3. Если аномалии с пометкой valid=false повторяются систематически на одном и том же оборудовании, инициировать внеплановый осмотр насоса и проверку калибровки датчиков давления и оборотов.
